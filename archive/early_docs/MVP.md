# 项目二 MVP 规格 — A Machine for Misunderstanding

> **日期**：2026-08-24（Day 1 冻结）
> **用途**：把项目从「概念方案」推进到「有声音、有 patch、可验证」的最小闭环。**本页是一页规格**，实现细节在 `workflow/README.md`，运行结果在 `workflow/运行记录.md`。
> **依据**：`review.md` 的 8/24–8/30 计划 Day 1 + 第五次追问方向（输入 = 现象学文本 → 黑箱模型 → 高维向量）。

---

## 0. 一句话

> **A 写一段现象学描述，黑箱模型把它压成一个高维向量，这个向量驱动 VCV 产生一段可听见的声音——先证明「文本 → 向量 → 声音」链路成立。**

MVP **不含** A/B 盲测、不含实时身体传感器、不含 Robin。先把声音这一层真正做出来。

---

## 1. 输入链（已定）

```text
A 的现象学文本描述
        ↓ ① 解释模型（黑箱）→ VAD 三元组（各 0–1 + confidence）
           MVP 先用 DeepSeek API 跑通；后替换为自微调模型（同接口 drop-in）
        ↓ ② Max 接收 + 归一化 + 映射
3 个声音控制值（density / brightness / stability）
        ↓ ③ OSC（带 ,f type tag）→ VCV
一个 patch（声音设计主体）→ 60–90s 声音
```

### 关键决策
- **模型（分两步，接口契约先行）**：
  - **现在（MVP）**：DeepSeek API 跑通整条 workflow。**接口契约 = 文本 → `{valence, arousal, dominance, confidence}` 结构化 JSON**，Max/VCV 全部按这个接口搭，模型选谁不阻塞 workflow。
  - **之后（升级）**：LoRA 微调 Qwen2.5-7B-Instruct（HPC/vLLM 部署），**同接口 drop-in 替换**——workflow 不改，只换后端模型。微调是作品的技术内容，但今天先不碰。
- **向量维度**：MVP 冻结 **VAD 三维**；**架构预留 6 维**（未来追加的 3 维待与吴老师对齐后命名，但 Max/VCV 的 OSC 协议从第一天就按 6 槽位设计，新维度只是补槽位，不改链路）。
- **中间层**：Max 负责接收 LLM 输出、归一化、映射、发 OSC——**Max 是逻辑中枢**；若 Max 接 DeepSeek API 不方便，用 Python-OSC 桥代替接收端，但**归一 + 映射逻辑仍放 Max**。
- **VCV 是声音设计主体**：patch 承载全部声音表达，不接受「默认 patch 交差」。

## 2. 三个声音参数与映射（每个都答 Why）

| 向量维度 | 含义 | 映射到 | Why（主题对应） |
|---|---|---|---|
| **Valence** 效价 | 积极 ↔ 消极 | **音色明暗**（滤波 cutoff / 泛音亮度） | 听感上最直觉的效价对应：亮 = 正、暗 = 负。明亮是声音的「表情」。 |
| **Arousal** 唤醒 | 安静 ↔ 激动 | **节奏密度 / 动态能量**（触发率、音符密度、响度） | 唤醒度的本质是能量水平——密度与力度是声音对能量的直接表达。 |
| **Dominance** 支配 | 被动 ↔ 主导 | **稳定性 / 失真**（连续性、失真量、间歇性） | 支配感是「控制 vs 失控」：支配高 → 稳定持续音；支配低 → 间歇、失真、不可预测。这正是黑箱机器的「失控层」。 |

**映射原则**（红线，来自概念文档 4.2）：
- 每一维的映射都要能回答 Why，不能是 `value → volume` 式任意映射。
- 每一维的**随机范围**和**边界**（0–1 各自允许走到哪）要写死，超出边界的值 clamp。
- 每一维的**失败行为**要定义：信号丢失 / 越界 / 空值时该维的默认行为。

## 3. 60–90s 声音结构（MVP 的「一段表达」）

输入是**一个** VAD 三元组（A 一段文本 → 一个向量），不是实时流。所以 60–90s 不是连续采样，而是**围绕这个向量锚点的一段声音叙事**：

| 时段 | 结构 | 声音做什么 |
|---|---|---|
| 0:00–0:25 | **建立** | 三个参数从「低 / 零」缓慢逼近向量锚点——A 的表达被「听见」的过程 |
| 0:25–0:55 | **展开** | 围绕锚点呼吸：三维各自缓慢变化并交叉（效价主导明暗、唤醒主导密度、支配主导稳定），有对比、有层次 |
| 0:55–1:30 | **收束** | 回到锚点，但**不完全回到起点**——留下一个未解尾音（communication gap 的种子：你以为你表达清楚了，其实没有） |

**锚点扫描的实现**：向量不变，用 Max 里的 LFO / 包络对三个参数做以锚点为中心的缓慢扫描（幅度受限），保证声音「活」而不脱离 A 的状态。

## 4. 暂不做（明确排除，防膨胀）

- ❌ Robin / 任何身体传感器（传感器方案整体后置，MVP 不接）
- ❌ A/B blind 盲测（Day 6 才做，MVP 只验证声音层）
- ❌ 实时 AI（每 5–10s 重解释是后置项，MVP 一次调用出向量即可）
- ❌ 6 维（协议预留槽位，不实现）
- ❌ 5 乐章长表演、多人实验、高维 PCA / 降维
- ❌ Serum、硬件模块（VCV + Max 已足够）

---

## 5. 验收标准（MVP 的「成立」定义）

1. **能听出差异**：同一个人，喂两段不同效价/唤醒/支配的文本，生成的 60–90s 声音在明暗、密度、稳定度上**可被听出差异**。
2. **链路真实**：`文本 → DeepSeek → Max → OSC → VCV → 音频` 每一步真实运行，不是手动改参数模拟。
3. **无削波**：60–90s 成品无明显削波和噪声失控，峰值留 6dB headroom。
4. **一份技术说明**：输入文本、模型输出向量、Max 映射表、VCV patch 截图、已知问题——别人能复现或检查。
